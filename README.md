# Інформаційна система керування кур'єрськими доставками (Варіант №21)

Клієнт–серверна інформаційна система керування кур'єрськими доставками, призначена для обліку клієнтів, кур'єрів, відправлень, розрахунку інтегрального показника ризику та супроводу замовлень доставки.

Основні сутності системи: клієнти (`Client`), кур'єри (`Courier`), відправлення (`Shipment`) та замовлення доставки (`DeliveryOrder` із життєвим циклом `CREATED -> ASSIGNED -> DELIVERED -> CANCELLED`). Через графічний інтерфейс JavaFX користувач може переглядати таблиці, виконувати CRUD-операції, перевіряти предметні обмеження переходів станів та запускати фоновий імпорт замовлень із CSV-файлу.

## Технології

* **Java 21** — основна мова розробки серверної та клієнтської частин.
* **Maven** — збірка модулів `server` і `client`, керування залежностями та запуск тестів (`mvn clean test`, `mvn clean package`, `mvn javafx:run`).
* **Servlet API 4.0.1 та Apache Tomcat 9.x** — обробка HTTP-запитів і розгортання серверного WAR-архіву.
* **MySQL / JDBC** — реляційне збереження даних у базі `delivery_db` та взаємодія з БД на рівні DAO.
* **Jackson** — серіалізація та десеріалізація JSON між клієнтом і сервером.
* **JavaFX** — настільний графічний інтерфейс користувача та фонове виконання задач (`Task`).
* **JUnit 5** — модульне тестування серверної бізнес-логіки.
* **Git** — контроль версій.

## Підготовка бази даних

1. Встановіть та запустіть сервер MySQL (або сумісний MariaDB, наприклад у складі XAMPP).
2. Відкрийте phpMyAdmin (або будь-який SQL-клієнт) та імпортуйте кореневий файл `database.sql`. Скрипт створить базу даних `delivery_db` у кодуванні `utf8mb4` із початковими тестовими записами.
3. Переконайтеся, що в базі `delivery_db` створено 4 таблиці:
    * `client`
    * `shipment`
    * `courier`
    * `delivery_order`
4. За потреби налаштуйте локальні параметри підключення до БД (`URL`, `USER`, `PASSWORD`) у класі `DBUtil` серверного модуля відповідно до конфігурації вашого локального MySQL-сервера (реальні паролі не зберігаються у публічному репозиторії).

## Запуск сервера

Команди Maven виконуються з каталогу `server`:

    cd server
    mvn clean test
    mvn clean package

1. Після успішної збірки скопіюйте згенерований WAR-файл із каталогу `server/target/` (`courier-delivery-server.war`) у теку `webapps/` сервера Apache Tomcat 9.x.
2. Запустіть Tomcat і переконайтеся, що в логах немає помилок розгортання або підключення до MySQL.
3. Перевірте доступність API у браузері, перейшовши за контрольним GET-маршрутом (наприклад,`http://localhost:8080/courier-delivery-server/clients`; `http://localhost:8080/courier-delivery-server/couriers`; `http://localhost:8080/courier-delivery-server/delivery-orders` або `http://localhost:8080/courier-delivery-server/shipments`) — у відповідь має повернутися коректний JSON-масив об'єктів.

## Запуск JavaFX-клієнта

Перед запуском клієнта мають працювати MySQL та розгорнутий у Tomcat серверний модуль.

З кореня репозиторію виконайте:

    cd client
    mvn javafx:run

* У разі помилок підключення або статусу `404` перевірте, чи запущений Tomcat і чи збігається назва контексту WAR-файлу.
* Запускати клієнт потрібно саме з робочого каталогу `client/`, оскільки відносний шлях до CSV-файлу (`sample-data/deliveries.csv`) обчислюється від нього.

## Тестування

Модульні тести JUnit 5 розміщені в `server/src/test/java/ua/edu/nupp/kpp/server/CourierServerUnitTest.java` і запускаються без потреби в Tomcat чи MySQL:

    cd server
    mvn clean test

Набір містить **16 unit-тестів**, які перевіряють:
* розрахунок фактора перевищення ваги `F1` (нижня межа `0.0` без перевищення ліміту та верхня межа `100.0` при надмірному перевищенні);
* обчислення інтегрального показника ризику (`I = 0.40 * F1 + 0.35 * F2 + 0.25 * F3`) та відхилення значень факторів поза діапазоном `0..100`;
* правила життєвого циклу замовлень у `DeliveryOrderService` (дозволені послідовні переходи `CREATED -> ASSIGNED`, `ASSIGNED -> DELIVERED`, `DELIVERED -> CANCELLED` та заборона недопустимих переходів);
* коректність роботи моделі `DeliveryOrder` та обробку некоректних вхідних даних.

## CSV-імпорт

* **Шлях до файлу:** `sample-data/deliveries.csv` (відносно каталогу `client/`).
* **Кодування:** `UTF-8`.
* **Формат:** роздільник `;`, 5 полів — `client_id;courier_id;shipment_id;order_date;total_cost`.
* **Маршрут обробки:** CSV-файл читається фоновим завданням `ImportDeliveriesTask` (JavaFX `Task`) і надсилає кожен запис через HTTP-клієнт на сервер (`Servlet -> Service -> DAO -> MySQL`), без прямого JDBC-доступу з клієнта.

**Порядок виконання:**
1. Запустіть MySQL, Tomcat та JavaFX-клієнт.
2. Переконайтеся, що `client_id`, `courier_id` та `shipment_id` у `deliveries.csv` відповідають реально чинним `id` у таблицях `client`, `courier` та `shipment`.
3. Відкрийте вкладку «Замовлення» та натисніть «Імпортувати CSV».
4. Простежте за `ProgressBar`, міткою статусу та автоматичним оновленням таблиці після завершення імпорту.

> **Увага щодо повторного імпорту:** перевірка на дублікати рядків при імпорті не реалізована, тому повторне натискання кнопки додасть ті самі записи в таблицю `delivery_order` ще раз із новими `id`.
